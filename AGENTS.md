# aika-waitlist

Next.js 16 (App Router), React 19, Tailwind CSS v4, and a self-hosted Payload 4
CMS backed by Postgres. The public waitlist is a landing page plus a small
mini-game; signups are sent to Brevo through `POST /api/waitlist`.

The CMS is optional at runtime. The public page and waitlist API do not read
from Payload, so the site works before a database is connected.

## Commands

- `pnpm dev` — start Next.js on <http://localhost:3000>.
- `pnpm build` — Payload + Next production build. Requires `DATABASE_URI` and
  `PAYLOAD_SECRET`.
- `pnpm start` — serve the production build.
- `pnpm generate:types` — regenerate `src/payload-types.ts`.
- `pnpm generate:importmap` — regenerate the Payload admin import map.
- `pnpm migrate:create` / `pnpm migrate` — create and apply Postgres migrations.
- `pnpm format` — format with oxfmt.

Vercel uses `scripts/vercel-build.mjs` through `vercel.json`. When
`DATABASE_URI` and `PAYLOAD_SECRET` are present it runs the full Payload build.
When either is missing it temporarily excludes `src/app/(payload)` and builds
the public site only, so previews work before the CMS is provisioned.

## Project structure

- `src/app/(frontend)/` — public landing page, layout, global styles, and
  `not-found.tsx`.
- `src/app/(frontend)/page.tsx` — client-side waitlist form and mini-game.
- `src/app/api/waitlist/route.ts` — Brevo integration and waitlist validation.
- `src/app/(payload)/` — generated Payload admin and API routes. Do not edit.
- `src/collections/` — `Admins`, `Media`, `Folders`, `Tags`, `Posts`.
- `src/payload.config.ts` — Payload config, Postgres adapter, storage, editor.
- `src/payload-types.ts` — generated by Payload; do not hand-edit.
- `src/lib/payload.ts` — shared `findBySlug()` / `findByField()` helpers.
- `public/assets/` — local SVG artwork used by the landing page.
- `public/fonts/` — self-hosted Plus Jakarta Sans and Roboto Mono.
- `scripts/vercel-build.mjs` — Vercel build entrypoint.

## Environment

`.env.local` is gitignored. `.env.example` is the tracked template.

| Variable | Purpose |
| --- | --- |
| `BREVO_API_KEY` | Brevo API v3 key. Server-only. |
| `BREVO_LIST_ID` | Brevo list ID for new signups. |
| `BREVO_SENDER_EMAIL` | Verified Brevo sender for the welcome email. |
| `DATABASE_URI` | Postgres connection string. Use a pooled URL on Vercel. |
| `PAYLOAD_SECRET` | Long random signing secret for admin sessions. |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob token for media uploads. |
| `NEXT_PUBLIC_SITE_URL` | Optional canonical URL for metadata. |

Never put a secret in `NEXT_PUBLIC_*`, client code, Payload documents, or
committed files. Do not print secret values in chat or logs. Add production
values in Vercel under **Project → Settings → Environment Variables**.

## Payload

- Use `buildConfig()` from `payload`; the Figma-hosted config is gone.
- Keep `postgresAdapter({ pool: { connectionString: process.env.DATABASE_URI } })`.
- Storage adapters belong in `storage: [...]`, not `plugins`. The Vercel Blob
  adapter is in `src/payload.config.ts`; without a token it falls back to local
  disk in development.
- The lexical editor is configured as the default editor.
- `src/migrations/` is the source of truth for the schema. Apply pending
  migrations with `pnpm migrate` after configuring a database. Production
  applies them automatically through `prodMigrations`; `push` is disabled so
  development and production stay in sync. For schema changes, generate a
  migration with `pnpm migrate:create` and commit it.
- Keep the built-in `Admins` and `Media` collections. `Admins` uses Payload
  email/password auth. The first admin can be created at `/admin` while the
  collection is empty; after that, only authenticated admins can create more.
- Do not add Figma, Figma SSO, or a Figma-hosted storage/auth plugin.
- Keep `withPayload` in `next.config.ts` and keep the generated
  `src/app/(payload)` route group intact.

## Data modeling

- Model the real domain rather than generic `items`.
- Use relationships for independently managed concepts.
- Public detail records need a unique indexed `slug` and a `[slug]` route.
  Use `findBySlug()` from `src/lib/payload.ts` and call `notFound()` when a
  record is missing.
- Render useful empty states and tolerate missing optional media.
- Keep user-facing pages under `src/app/(frontend)/`.
- Do not replace durable Payload data with static arrays.

## Schema safety

Before changing an existing schema, classify the change:

- Greenfield additive fields and new collections can usually proceed.
- Optional fields and new relationships can proceed with a concise preview.
- Deletes, renames, type changes, `required`/`unique` constraints, relationship
  cardinality changes, and bulk document updates are destructive or ambiguous.
  Pause and ask for confirmation with the affected fields, data-loss risk, and
  migration/preservation plan.

Preserve the document ID type in `payload-types.ts`; do not assume numeric IDs.
For user-facing Local API calls use `overrideAccess: false` and pass the
authenticated user when one exists. Enforce durable invariants and access rules
at the collection boundary, not only in the UI.

## Access and security

- The waitlist route validates and limits input, handles the honeypot, and rate
  limits submissions.
- Public users must not be able to list, read, update, or delete private records.
- Do not expose Payload Admin access through public app signup. `Admins` is for
  CMS editors only.
- Keep `.env.local` and Vercel secrets private.

## Images and styling

- Tailwind CSS v4 is loaded by `@import "tailwindcss"` in
  `src/app/(frontend)/styles.css`.
- Use Tailwind utilities in JSX; keep `styles.css` for the Tailwind import,
  theme tokens, font faces, and truly global base styles.
- Fonts are self-hosted in `public/fonts/`; do not reintroduce remote Figma font
  URLs.
- For Payload-managed images, model uploads through the `Media` collection and
  pass the upload URL to `next/image`. No custom Figma image loader is needed.
- Vercel's filesystem is ephemeral; set `BLOB_READ_WRITE_TOKEN` for persistent
  media uploads in production.

## Verification

Before finishing a change:

1. Run `pnpm exec tsc --noEmit`.
2. Run `node scripts/vercel-build.mjs` and confirm the public routes build.
3. When `DATABASE_URI` and `PAYLOAD_SECRET` are available, run `pnpm build` and
   check the generated route table includes `/admin` and the Payload API.
4. Visit `/`, `/api/waitlist`, and (when configured) `/admin`.
5. Confirm no new Figma imports, scripts, or remote Figma assets were added.
